# finapp — план разработки

Личный учёт доходов и расходов. Веб-версия v1 с регистрацией по приглашению, доступна по https://<domain>. Android-приложение — следующий этап, на том же API.

## 1. Стек

| Слой | Технология |
|---|---|
| Фронтенд | React + TypeScript + Vite, Tailwind CSS, shadcn/ui, Framer Motion, Recharts, Lucide |
| Бэкенд | FastAPI (Python), SQLAlchemy, Alembic |
| База | SQLite (файл в volume контейнера), переход на PostgreSQL при росте |
| Аутентификация | email + пароль (argon2), сессия в httpOnly cookie (JWT, SameSite=Lax, Secure) |
| Веб-сервер | Nginx: статика React + reverse proxy на `/api` |
| HTTPS | Let's Encrypt через certbot (HTTP-01 на порту 80) |
| Запуск | Docker Compose на хосте Ubuntu 26.04 LTS |

## 2. Деплой

```
Интернет → <domain> (A → <host-ip>)
   → хост Ubuntu, проброс 80/443 на контейнер nginx
      → контейнер nginx : статика (/), /api/* → контейнер api
      → контейнер api   : FastAPI + SQLite (volume), порт не публикуется наружу
      → контейнер certbot : продление сертификатов
```

- Отдельный системный пользователь `finapp` на хосте, владеет каталогом проекта и данными. Доступ к Docker через группу `docker`, без sudo.
- Секреты (ключ сессий, пароль первого администратора) лежат в `.env` на хосте с правами 600. В git не попадают.
- Файрвол (ufw): открыты 22 (SSH только по ключу), 80, 443.
- Бэкап: ежедневный `sqlite3 .backup` в отдельный каталог, хранить 14 дней.
- Деплой: `git pull` на хосте и `docker compose up -d --build`. Для git на хосте нужен deploy key только на чтение.

## 3. Регистрация по приглашению

- Публичной регистрации нет. Страница `/signup` доступна только с кодом приглашения.
- Первый администратор создаётся командой CLI на хосте (`docker compose exec api python -m app.cli create-admin`).
- Администратор создаёт инвайты: одноразовый код, срок действия 7 дней. Инвайт привязан к email.
- Вход: email + пароль. Ограничение попыток входа (5 неудачных за 15 минут на email и IP).
- Восстановление пароля в v1 — через администратора (сброс). Почтовый сервис не подключаем.

## 4. Функции v1

| Функция | Что делает |
|---|---|
| Вход / выход | Страница входа, выход со всех устройств |
| Регистрация по инвайту | Ввод кода приглашения, имя, пароль |
| Баланс за месяц | Доходы, расходы, итог; переключение месяцев |
| Операции | Добавить / редактировать / удалить (с подтверждением). Тип, сумма, категория, дата, заметка |
| История | Фильтры по типу, категории, дате; поиск по заметке |
| Категории | Стандартный набор при регистрации; добавить, переименовать, удалить (если нет операций) |
| Статистика | Круговая диаграмма расходов по категориям, столбцы по месяцам |
| Профиль | Смена пароля, тема (светлая/тёмная), экспорт JSON, удаление аккаунта |
| Админка | Создать инвайт, список пользователей, блокировка аккаунта |

Вне v1: графики бюджетов, несколько счетов и валют, повторяющиеся операции, переводы, вход через Google, экспорт CSV, синхронизация с Android.

## 5. Данные

- **User:** id, email (уникальный), имя, password_hash, role (user / admin), is_active, created_at.
- **Invite:** id, code_hash, email, created_by, expires_at, used_at.
- **Category:** id, user_id, название, тип (INCOME / EXPENSE / BOTH), цвет, иконка, updated_at.
- **Transaction:** id, user_id, type (INCOME / EXPENSE), amount_minor (целое число, копейки), category_id, date (YYYY-MM-DD), note, created_at, updated_at.
- Все запросы фильтруются по `user_id` текущего пользователя.
- Экспорт JSON использует ту же схему. Её же будет читать Android-приложение.

## 6. Экраны

Публичные: Вход, Регистрация по инвайту.
После входа: Главная, История, Статистика, Категории, Профиль. Админка — отдельный раздел для роли admin.

Мобильная версия — нижняя навигация, на десктопе — боковое меню.

## 7. Дизайн

- Mobile-first, одна колонка до 480px.
- Карточки с мягкими тенями, крупные цифры баланса, акцентные градиенты.
- Доходы зелёным, расходы красным. Светлая и тёмная тема по настройкам системы или вручную.
- Деньги: `1 234,56 ₽`. Даты: `9 ноября 2026`.
- Интерфейс только на русском.
- Пустые состояния с подсказкой, понятные ошибки ввода, подтверждение опасных действий.

## 8. Безопасность

- HTTPS с редиректом с HTTP, HSTS.
- Пароли: argon2, минимум 10 символов.
- Cookie: `Secure`, `HttpOnly`, `SameSite=Lax`.
- Ограничение размера тела запроса, валидация всех входных данных (pydantic).
- Порт API не публикуется наружу, доступ только через Nginx.
- Заголовки безопасности в Nginx: CSP, X-Content-Type-Options, Referrer-Policy.
- Обновления ОС (unattended-upgrades) и образов контейнеров.

## 9. Этапы

| Этап | Результат | Готово, когда |
|---|---|---|
| 1. Каркас | Vite + React + TS, Tailwind, роутинг, дизайн-система, Docker Compose | `docker compose up` поднимает фронт и API на localhost |
| 2. Авторизация | Вход, инвайты, админ-команда, защищённые маршруты | Без входа `/` недоступен; регистрация без инвайта отклоняется; пароль в БД в виде хэша |
| 3. Операции и категории | CRUD на сервере и в UI | Данные видны после входа с другого браузера |
| 4. Главная и статистика | Баланс, фильтры, графики | Суммы совпадают с ручным подсчётом на тестовом наборе |
| 5. Деплой | Nginx, certbot, ufw, бэкапы на хосте | https://<domain> открывается с валидным сертификатом |
| 6. Полировка | Профиль, тёмная тема, анимации, экспорт/импорт | Экспорт и импорт проходят круг без потерь |

## 10. Открыто

- Проброс портов 80 и 443 на хост (делает владелец).
- Редирект `www.<domain>` на `<domain>`: сейчас A-запись `www` указывает на `<old-www-ip>`. Либо поменять её на `<host-ip>`, либо не использовать.
- Доступ к хосту для развёртывания (SSH-ключ или запуск командами владельцем).
- Дата выхода на Android — после стабилизации веб-версии.
